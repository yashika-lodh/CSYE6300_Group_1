Dynamic Pricing Engine

Direct-to-Consumer (DTC) retail brands often struggle with manual pricing across multi-channel environments like Shopify, native web stores, and social commerce platforms—lacking a real-time demand feedback loop. This application is a live demonstration of a high-throughput, automated pricing system built with nine core Object-Oriented Design Patterns.

System Architecture & Execution Pipeline

The pricing engine processes raw market signals through an automated event-driven pipeline: raw demand history is parsed by an adapter, evaluated by a forecaster to select a runtime pricing strategy, encapsulated inside decorated commands for compliance logging, dispatched to multi-channel endpoints via factory methods, and perpetually synchronized with database storage through a thread-safe Observer feedback loop.

Nine Core Design Patterns

1. Singleton
Inventory

One thread-safe stock ledger shared by every channel.

2. Observer
InventoryObserver, RepricingTriggerObserver, InventoryPersistenceObserver

Two independent subscribers react to a stock change: one triggers a reprice, one writes through to the DB.

3. Strategy
PricingStrategy, PricingStrategySelector

Interchangeable pricing algorithms chosen at runtime by demand trend.

4. Factory Method
SalesChannelFactory

Centralizes creation of every channel type behind one call.

5. Command
PricingCommand, UpdatePriceCommand, PricingCommandInvoker

Encapsulates a price change so it can be queued, executed, and undone.

6. Decorator
AuditLoggingCommandDecorator

Wraps any command with compliance logging without touching its own logic.

7. Adapter
DemandSignalAdapter

Translates the external raw demand feed shape into the engine's domain model.

8. Template Method
RepricingWorkflow, StandardRepricingWorkflow, ScheduledRepricingWorkflow

One fixed fetch→validate→execute→log skeleton, run on-demand or on a timer.

9. Repository
InventoryRepository, DemandSignalRepository

Decouples domain logic from storage (JPA/H2 for stock, CSV for demand).
