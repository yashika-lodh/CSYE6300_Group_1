Dynamic Pricing Engine

Multi-Channel DTC Retail — CSYE 6300, Group 1

DTC brands selling across Shopify, their own website, and social commerce price manually and inconsistently, with no feedback loop back to demand. This engine forecasts demand in real time, auto-selects a pricing strategy per market conditions, syncs prices across every channel, and keeps a full audit trail of every price change — built as a live demonstration of nine classic software design patterns working together.

Architecture

One pipeline, one feedback loop: demand history feeds a forecaster, the forecaster's trend picks a pricing strategy, the resulting price change is executed and logged, and every stock change loops back in automatically through an Observer.

Nine Design Patterns

Every core class names the pattern it implements directly in its Javadoc — this system is a working example of each, not just a textbook description.

Singleton

Inventory

Exactly one thread-safe stock ledger shared by every sales channel.

Observer

InventoryObserver, RepricingTriggerObserver, InventoryPersistenceObserver

Two independent subscribers react to a stock change — one triggers a reprice, one writes through to the DB.

Strategy

PricingStrategy, PricingStrategySelector

Interchangeable pricing algorithms chosen at runtime by demand trend: cost-plus, competitor-aware, or inventory-aging.

Factory Method

SalesChannelFactory

Centralizes creation of every channel type (Shopify, own website, social commerce) behind one call.

Command

PricingCommand, UpdatePriceCommand, PricingCommandInvoker

Encapsulates a price change so it can be queued, executed, and undone uniformly across channels.

Decorator

AuditLoggingCommandDecorator

Wraps any command with compliance logging without touching the command's own execute/undo logic.

Adapter

DemandSignalAdapter

Translates the external raw demand feed shape into the engine's own domain model.

Template Method

RepricingWorkflow, StandardRepricingWorkflow, ScheduledRepricingWorkflow

One fixed fetch → validate → execute → log skeleton, run either on-demand or on a timer.

Repository

InventoryRepository, DemandSignalRepository

Decouples domain logic from storage — JPA/H2 for stock, CSV for demand history.

Tech Stack

  • Java 21
  • Spring Boot 3.3 (REST API)
  • Hibernate/JPA + H2 (persistence)
  • JUnit 5 + Spring Boot Test
  • SLF4J / Logback
  • Shopify Admin GraphQL API
