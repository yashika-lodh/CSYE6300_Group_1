Dynamic Pricing Engine

Multi-Channel DTC Retail — CSYE 6300, Group 1

Direct-to-consumer brands set prices by hand across Shopify, their own storefront, and social commerce — with no demand feedback loop tying it together. This project is a live demonstration of nine classic design patterns cooperating to reprice inventory automatically as demand shifts.

01 — ARCHITECTURE

A closed-loop repricing pipeline

Demand history feeds a forecaster that classifies the trend. A strategy is selected at runtime to calculate an updated price. A decorator wraps the price update command for compliance audit logging, while the factory distributes new prices to multi-channel endpoints. An observer feedback loop keeps inventory synchronized across all channels.

02 — DESIGN PATTERNS

Nine Core Design Patterns

1. Singleton
Inventory

One thread-safe stock ledger shared by every channel.

2. Observer
InventoryObserver, RepricingTriggerObserver, InventoryPersistenceObserver

Independent subscribers react to a stock change: one triggers a reprice, one writes through to the DB.

3. Strategy
PricingStrategy, PricingStrategySelector

Interchangeable pricing algorithms chosen at runtime by demand trend.

4. Factory Method
SalesChannelFactory

Centralizes creation of every channel type behind one call.

5. Command
PricingCommand, UpdatePriceCommand, PricingCommandInvoker

Encapsulates a price change so it can be queued, executed, and undone.

6. Decorator
AuditLoggingCommandDecorator

Wraps any command with compliance logging without touching its own logic.

7. Adapter
DemandSignalAdapter

Translates the external raw demand feed shape into the engine's domain model.

8. Template Method
RepricingWorkflow, StandardRepricingWorkflow, ScheduledRepricingWorkflow

One fixed fetch→validate→execute→log skeleton, run on-demand or on a timer.

9. Repository
InventoryRepository, DemandSignalRepository

Decouples domain logic from storage (JPA/H2 for stock, CSV for demand).
